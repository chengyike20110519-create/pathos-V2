# PathOS 数据运行规则

## 数据边界

- 地图摘要只返回学校 ID、名称、中文名、坐标、城市/州、排名层级和数据版本；在数据库内投影字段，不传完整研究 JSON。
- 点击学校后才请求 `endpoint=university&id=...`，详情包含专业、费用、录取、本科人数、来源和核验状态。
- 单校详情只读取该卡使用的 Scorecard 字段，以及该校引用的来源；不再为一张卡跨网络传输整份研究记录和全站来源索引。
- 摘要客户端和服务端缓存均为 5 分钟；详情客户端 5 分钟、服务端 2 分钟。成功响应浏览器缓存 60 秒、边缘缓存 5 分钟，失败不缓存。
- 初始摘要请求随 HTML 预加载，和地图脚本并行；地图范围按 5 度向外取整并延迟 250 毫秒，已覆盖范围内移动不重查。刷新保留旧点，失败提示并保留上次结果，不伪装成最新结果。
- 页脚次级入口关闭自动预取，避免在地图首屏并行下载计算器、专业档案、账户等无关页面脚本；导航本身仍可正常使用。
- 专业目录索引 `endpoint=program-catalog` 仅在专业探索页面加载，5 分钟缓存。当前上限 5,000 校；扩充学校规模时须改为服务端按专业过滤和分页，不能默默截断。
- 专业筛选打开时才读取 `endpoint=program-options&q=...`，最多 60 个名称和去重学校数，不传全校专业明细。选中后 `endpoint=universities&program=...` 在数据库内精确过滤目录名称，可叠加州筛选。计数不是专业实力排名。
- 摘要接口默认最多返回 250 条、上限 500 条；按州筛选优先于全量查询。

## 专业展示和证据

- 卡片顺序：特色/有证据的优势 → 专业速览 → 可展开、搜索的全部已收录专业。普通开设关系不能推出优势、热门或就业好。
- 特色专业存在 `school_confirmed_facts` 的 `program_spotlights_v1` 中，每条有英文标准名、中文名、特色理由、官方来源和核验日期；学校及专业事实不硬编码到组件。
- 已审核录入文件 `data/reviewed/program-spotlights.json` 用于有来源的定向导入；`scripts/import-program-spotlights.ts` 默认只检查，显式 `--apply` 才写这类事实。不会运行其他迁移。
- 特色是编辑精选，不代表独有/实力排行。优势记录须有本科层级、榜单年份、发布机构、比较范围、名次、发布日期、并列状态及可追溯来源；研究生、综合大学或范围不明的排名拒绝展示。并列未披露时保存 null 并显示说明，不猜测为独占名次。
- `地图 → 学校卡 → 专业探索 → 相关学校/学校完整档案`。专业探索按标准名精确关联；近似名称不直接合并。相关学校清楚标为“开设”，未知介绍和未核实优势留空。
- 地图保留清晰圆点；悬停显示校名，选中点始终单独显示。按屏幕距离分组的数字代表附近学校数，点击打开可访问的学校列表，即使坐标完全相同仍可分别选择；分组成员不再重复绘制 GPU 圆点。
- 学校列表与地图双向联动，悬停列表可突出地图对应点/分组，选择后定位并打开卡片。手机选校后收起列表，卡片默认半屏；360 像素窄屏的筛选面板按工具栏实际高度定位。
- 州及专业条件保存在 URL，刷新可恢复；无结果说明收录范围，并提供清除筛选入口。专业仍按同名目录关联，不能据此推断某校没有相近但不同名称的项目。
- 本轮综合排名沿用原收录值，未混入局部学校的 2027 新综合排名。已核验优势样例为 MIT（机械、化工、经济学）和 Georgia Tech（工业、土木、环境工程），均为学校 2026-09-22 官方披露的 2027 本科榜单，核验日 2026-10-19。不是全库优势数据已经补齐。
- 原始披露：[MIT](https://news.mit.edu/2026/mit-named-nations-top-university-us-news-0922)、[Georgia Tech](https://coe.gatech.edu/news/2026/09/undergrad-engineering-reaches-no-2-2027-us-news-rankings)。
- 选择州只筛选院校，不自动打开缺乏真实市级指标的城市色块/气泡；城市聚合功能不作为默认学校探索入口。

## 本轮验收（2026-10-19）

- 生产构建、类型检查和 46 项针对性测试通过；不是宣称旧有全量测试全部通过。
- UIC 完整档案旧字段 `admissions.acceptanceRate: {}` 曾使来源数量组件读取不存在的 `sourceIds.length` 而崩溃；在响应解析边界统一补齐缺省结构，未知数值保持 null、来源保持空数组，未伪造事实。完整档案路径已加入实际浏览器回归检查。
- `scripts/check-map-runtime.ts` 使用真实浏览器和当前后端，检查分组可选、点位定位、筛选恢复、空结果恢复、信息卡、全部专业搜索、专业跳转，以及 360/390 像素手机布局。报告及截图更新到原 `test-results/`，没有另建站点版本。
- `scripts/audit-map-details.ts` 只读检查 94 校详情，94/94 成功且专业及来源均非空；接口有效不等于所有历史字段均已重新核实，也不等于 94 校优势专业已经补齐。
- 正式环境多轮冷启动点位出现耗时分别约 7.9 秒、2.7 秒、4.6 秒，首开信息卡约 2.7 秒、1.9 秒、1.7 秒。保留慢样本，不只报告最快值。
- 后续一次网络异常样本中，数据库出现 ETIMEDOUT，学校摘要自动重试后约 12.2 秒出现，详情重试后约 26.8 秒完成。这说明外部连接稳定性仍未达标；不能宣称所有场景流畅或把重试耗时从结果中排除。
- 修复完成后的末轮完整动线检查通过，包含 UIC 完整档案和手机端，无页面异常；服务预热后点位约 0.67 秒、首开详情约 6.79 秒、缓存重开约 0.45 秒。前两项分别受服务缓存和连接波动影响，不可当作稳定 SLA。数据库两个端口的独立新连接 SELECT 1 均曾在约 1.2 秒成功，仅能说明不是持续断网，不能排除连接池或链路的间歇性故障。
- 带资源计时的末轮摘要响应约 4.0 秒、传输约 1.3 KB（科罗拉多州），地图主要脚本约 0.12 秒完成传输。当前主要等待在后端摘要请求；不能把全部等待时间等同于数据库执行时间，也不能据此推断数据库容量过大。进一步定位需拆分连接、SQL、网络时延；正式部署应结合服务与数据库地域测量。

## 备份

使用 Supabase session pooler 的 `DIRECT_URL` 执行：

```sh
DIRECT_URL='***' ./scripts/backup-supabase.sh
```

不要把连接字符串提交到 Git、前端代码或浏览器。备份文件应放在受控且加密的位置，并定期恢复演练。
