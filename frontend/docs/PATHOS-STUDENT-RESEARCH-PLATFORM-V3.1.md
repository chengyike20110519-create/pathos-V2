# PathOS V3.1 学生信息研究平台执行规格

## 1. 产品定位

PathOS 面向需要快速理解美国大学的学生与家庭，核心价值是:

```text
找学校 -> 3 分钟读懂学校 -> 核查字段与来源 -> 横向比较 -> 看多年趋势 -> 保存研究 -> 导出引用
```

PathOS 不是申请管理系统、录取概率预测器、顾问协作系统或咨询交付系统。现有决策类功能暂不删除，但从主导航和首页主叙事中降级，避免用户误解产品边界。

## 2. 非目标

- 不输出“冲刺 / 匹配 / 保底”结论。
- 不预测录取概率。
- 不替学生做申请决策。
- 不把营销话术包装成数据。
- 不在缺失年份之间插值。
- 不把 Preview 数据标记为 Approved Fact。
- 不为演示效果补造假学校照片、排名或费用。

## 3. 页面架构

### 3.1 学校 / Schools

- `/map`: 学校发现入口，保留地理、城市和学校筛选。
- `/search`: 全局检索，保留最近搜索与本地保存搜索。
- `/guides`: 大学指南索引。
- `/university/[id]`: 学校研究档案，下一节重构。

### 3.2 专业 / Majors

- `/majors`: 专业索引。
- `/majors/[slug]`: 专业定义、边界、代表学校与要求。
- `/topics/cs-engineering`: 工程与计算机专题。

### 3.3 趋势 / Trends

`/trends` 是 V3.1 的新核心模块:

- 最多 4 所学校同屏。
- 指标 V1: 录取率、学费、SAT、GPA。
- 每条序列显示来源、数据时点、核验者、置信度。
- 缺失年份保留空档，不连线、不插值。
- 提供研究用 CSV 导出，包含空值与来源元数据。

### 3.4 费用 / Costs

- `/costs`: 费用中心，明确学费、总成本、生活费和统计口径。
- `/calculator`: 预算计算器，只做可解释计算，不做支付或套餐。

### 3.5 我的研究 / My Research

- `/compare`: 保留 4 校比较，强调字段差异而非优劣决策。
- `/followed`: 关注学校与信息动态。
- `/research`: V3.1 个人研究台。以研究问题为主轴，组织学校样本、证据笔记、相关资讯、比较视图和趋势视图；V1 状态保存在本机浏览器，不冒充账号同步。
- `/workbench/shortlists`: 渐进更名为研究集合。
- `/s/home`: 旧数据工作台过渡入口。
- AI 评估、清单分析、自主测验保留但从主叙事降级。

## 4. 学校速览规格

参考大学官网常用结构的可取部分: 强学校身份、紧凑指标条、分区信息、位置语境、图表与快捷入口。PathOS 不复制亮蓝营销样式，而用现有 Ink / Paper / Copper 企业级体系。

### 4.1 首屏结构

1. 学校身份区: 中英文校名、地点、数据层、数据集版本。
2. 8 个核心指标:
   - 全国排名
   - 录取率
   - 本科 / 总在校生
   - 学费或费用区间
   - SAT 区间
   - 师生比
   - 毕业率
   - 标化政策
3. 每个指标必须展示:
   - 数值或明确缺失原因
   - 学术年份 / 参考年份
   - 口径或适用人群
   - Preview / Approved 状态
   - 来源数量或来源入口
4. 研究动作:
   - 加入比较
   - 加入研究集合
   - 打开费用
   - 查看趋势
5. 数据覆盖: 核心字段可用率、缺失字段和警告，不把覆盖率包装成学校好坏。

### 4.2 趋势摘要

- 有真实 `timeSeries` 时显示 Sparkline 与序列区间。
- 没有序列时显示“该校暂未发布已核验时序数据”。
- Sparkline 不夸大小幅波动，坐标从 0 开始仅用于非负指标。

## 5. 数据治理

| 层 | 用途 | 展示规则 |
| --- | --- | --- |
| Approved Fact | 已审核字段 | 绿色来源状态，展示抓取与审核时间 |
| Preview | 结构化预览 | 明确 Preview 标识，不得升级为已审核 |
| Missing | 缺失字段 | 保留缺失原因与适用口径 |

### 必须保存的元数据

- `academicYear`
- `applicantScope`
- `source`
- `sourceUrl`
- `retrievedAt`
- `reviewedAt`
- `confidence`
- `nullReason`
- `datasetVersion`

## 6. UI 与动效原则

- 首屏服务于研究效率，不用营销 hero 替代数据入口。
- 信息密度优先，但每行保留足够呼吸感。
- 图标使用 lucide，不用文本按钮替代明确图标动作。
- 滚动动效只用于进入、层级和反馈，不阻塞阅读。
- `prefers-reduced-motion` 下全部回到静态结果。
- 键盘焦点可见，触控目标不小于 44px。
- 企业色继续使用 Ink、Paper、Copper、Data Blue、Approved Green、Warning Amber。
